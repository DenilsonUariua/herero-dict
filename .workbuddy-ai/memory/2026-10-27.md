# 2026-10-27

## UX overhaul: sentence translation on the home page + copy/share into chat

User asked (a) whether typing a sentence and getting the other language is possible,
(b) to make copying words into WhatsApp/Messenger easier, (c) for general UX improvements.

Answer to (a): it already existed at `/translate` (RAG pipeline from the previous session).
The problem was discoverability, not capability — plus a preemptive "needs a language model"
alert that fired whenever `probeServer()` failed (i.e. every `npm run dev` without `dev:full`),
making a working feature look broken.

### What changed
- **Home is now the translator.** `src/components/translate/QuickTranslate.tsx` renders the
  same composer + result card in the hero; browse/word-of-the-day/search moved below.
- **Shared state machine**: `src/hooks/useSentenceTranslation.ts` (extracted from Translate.tsx)
  is used by both the home widget and `/translate`, so the two cannot drift. The RAG module is
  `await import()`-ed on first translate to keep it out of the first paint.
- **Copy/share layer**: `src/lib/clipboard.ts` (async clipboard + `execCommand` fallback —
  `navigator.clipboard` is missing in insecure contexts and in-app webviews, which is how a lot
  of this traffic arrives), `src/lib/share.ts` (native Web Share, `wa.me`, `t.me`, `sms:`,
  plain-text formatters), `CopyButton.tsx`, `ShareMenu.tsx`.
- **Direction guard**: `src/lib/lang-detect.ts` scores English stopwords vs Otjiherero
  prefixes/particles and offers "Switch direction" when the text looks like the wrong language.
  Deliberately conservative — a false prompt is worse than no prompt. Short prefixes
  (`ok`, `om`, `ov`) were dropped because they match "okay"/"overall".
- **Display formatting**: `src/lib/word-format.ts` — `displayHeadword` (source headwords are
  shouted caps), `splitHerero` (strips `/…/`, trailing stops, lifts `(ozo-)` into a `pl. ozo-`
  badge), `formatExample` (sentence-cases the English half of `EN/HZ` example pairs).
- **Browse fixes**: "Load more" replaced the 279-page dropdown (page cache TTL cut from 7 days
  to 10 minutes — a community dictionary changes when corrections land; the full word list keeps
  the long TTL for offline). Search debounced 300 ms (it fired a request per keystroke),
  bilingual placeholder, clear button, skeletons, visible error state (was swallowed), footer
  un-fixed (it overlapped cards), message popup converted to a Radix dialog with a one-off hint
  instead of a bubble that bounced every 15 s.
- **Word tab searches both languages at once** — typing `omuatje` while in `en-hz` used to
  return an empty state.
- **Perf**: routes lazy-loaded (Admin chunk 47 kB no longer in the first load), og:/twitter:
  meta added (sharing the link in WhatsApp showed no title), preconnect to Appwrite.
- `public/lexicon.json` was regenerated by `prebuild` (1671 → 2207 entries); it is committed
  on purpose, so the diff is expected.

### Verification
Headless Chrome over CDP (`/tmp/cdp.mjs`, temp only) with `Emulation.setFocusEmulationEnabled`
+ `Browser.grantPermissions` — needed because `navigator.clipboard` throws "Document is not
focused" in headless. Confirmed: sentence EN→HZ via the real Gemini proxy, clipboard contains
`U tura pi?` / `Aardvark (African Ant-Bear) — ondji-mbandjimba`, share menu items, load-more
24→48, no horizontal overflow at 390 px, typecheck + `npm run build` clean.

### Still open
- PWA precaches ~3.3 MB (lexicon included) on first visit — deliberate for offline, but heavy
  on mobile data. Option: move `lexicon.json` to a runtime cache.
- Home shows the Appwrite total (2,207) while `/translate` shows the lexicon count; they track
  the same source after `build:lexicon` but drift until a rebuild.
- `npm run lint` still fails on pre-existing errors in `src/components/ui/*` and
  `tailwind.config.ts` (not touched this session).
